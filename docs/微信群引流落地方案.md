# 微信群引流服务（group-entry）落地方案

> 本文档是需求与实现契约。实现进度更新到文末「实现进度」。

## 一、背景与目标

开源项目（silkpulse / TsFullStack / ccdd / mcpserver / vite-plugin-pilot）需要把 GitHub 用户引流到微信交流群。核心约束：

1. **微信群二维码通常只有 7 天有效期，群满后也不能继续扫码入群**——不能在 README 放静态群码
2. **博主拒绝定时维护**——没人进群时必须零操作
3. **README 一旦发布永不再改**——入口链接必须永久有效
4. 链路里的长期锚点：**公众号二维码** + **本项目动态服务**
5. 多个项目/渠道可共享同一个私域空间（公众号引导 + 群码池）；来源项目用链接 ?from= 参数记录，不建实体

## 二、总体链路

```text
GitHub README（永不改）
  ├─ 图片形式：![](https://<域名>/group/<空间名>.png?from=<来源>)   ← 动态图
  └─ 链接形式：https://<域名>/group/<空间名>?from=<来源>            ← 落地页
        ↓ 空间池内有有效群码
当前微信群二维码（扫码入群）+ 公众号二维码（长期关注入口）
        ↓ 群码过期、群满、停用或缺失
公众号二维码与关注引导（主要入群方式）
```

维护模型为**事件驱动，非定时驱动**：管理员在群满或收到更新需求时上传新群码；服务不运行 cron，也不探测微信侧真实群状态。公开页始终保留公众号，避免群码失效后用户失去联系入口。

## 三、功能需求

### 3.1 动态图片接口

`GET /group/:space.png`

- 项目池内有有效群码：返回当前群码图片流，可被 GitHub README 引用
- 无有效群码：返回 200 提示 SVG，文案为「暂时无法扫码入群」并引导关注公众号；不能返回 404 或裂图
- 出码规则与落地页一致：同空间共享当前群码
- 动态图使用 5 分钟缓存，落地页不使用缓存

### 3.2 落地页接口

`GET /group/:space`

- 有有效群码：展示「扫码加入微信群」、群名称、群码大图、预计过期时间，同时展示公众号卡片
- 无有效群码：展示「暂时无法扫码入群」，说明可能过期、群满或停用，并将公众号作为主要引导
- 公众号卡片展示后台配置的名称、二维码、关注引导语和回复关键词
- 页面移动端优先，不依赖外部字体或被墙资源；群码以 data URL 内嵌，公众号图片由受控路由提供
- 页面 `Cache-Control: no-store`，保证状态切换后刷新即可看到最新内容

### 3.3 私域空间、来源参数与群码池

数据关系固定为（2026-10 精简后的最终模型）：

```text
GroupSpace（私域空间：公众号引导 + 群码池）
  └─ 1-N GroupQRCode（微信群码池，空间内共享）
GroupStatDaily（统计：date + space + from 联合主键）
```

- **项目不建实体**：公开链接就是 `/group/<空间名>`，永久不变；「用户从哪个项目/渠道来」用链接上的 `?from=` 参数记录（自由文本，`[a-zA-Z0-9_-]{0,64}`，非法值视为空）
- 群码池按 `status='ACTIVE'`、`uploadedAt ASC` 排队，第一张未过期的群码为当前出码
- 上传新码只加入等待队列，**不会顶掉当前有效码**；同一池可有多条 `ACTIVE` 记录，但只有一个 `serving` 当前码
- 当前群满后，管理员将其标记为 `FULL`，公开链接自动切到下一张有效码
- `ARCHIVED` 表示手动停用；`FULL` 表示群已满；两者都不参与出码，可按需重新排队
- 不同空间的群码池相互隔离；多个项目/渠道共享同一空间时，靠 `from` 参数区分统计

### 3.4 管理页面与接口

后台页面 `/admin/groupEntry` 提供：

- 私域空间创建与删除
- 每空间独立的公众号配置：名称、回复关键词、关注引导语、二维码上传与预览
- 空间维度群码上传、预览、等待顺序、当前出码状态、标记群满、停用和重新排队
- 公开链接生成：输入 `from` 参数即可复制带来源的完整链接
- 按 空间+来源（from） 查看 PV/UV 统计和切换统计范围

页面调用管理 RPC，复用登录会话并由服务端 `requireAdmin()` 校验管理员角色；浏览器不保存独立群码管理令牌。

独立 HTTP API 保留给旧脚本/自动化工具，使用 `x-admin-token`：

- `POST /group/admin/qrcode`：multipart 字段 `space`（兼容旧字段名 `entry`）即空间名，空间不存在自动创建
- `GET /group/admin/qrcodes`：列出扁平化群码记录，不暴露本地图片路径
- `POST /group/admin/qrcode/:id/archive`：停用指定群码
- `GET /group/admin/stats?days=30`：查询统计

独立 API 的新码同样进入空间 FIFO 池，不归档其他有效码。上传成功后可按既有 `notifyUrl` 配置回调通知博主。

### 3.5 引流埋点统计

- 动态图和落地页分别记 PV；落地页额外记 UV（当日 cookie）
- 按 `date + space + from` 聚合到 `GroupStatDaily`：imgPv、pagePv、pageUv
- `from` 来自链接参数，用于判断不同 repo、渠道的实际引流效果；不带 `from` 的访问记入空字符串行

### 3.6 群码与公众号规则

- **微信群码**：默认有效期 7 天（168h），从上传时刻起算；`GroupQRCode` 只保存这类限时群码
- **群满状态**：微信侧无法由服务端自动探测，管理员确认群满后手动标记 `FULL`
- **提前失效**：公开判断包含 5 分钟提前量；管理列表的 `effective` 使用同一规则，宁可提前切换也不展示临界死码
- **公众号**：配置随 `GroupSpace` 存储（officialName / officialReplyKeyword / officialGuideText / officialQrImagePath），每个空间独立，不套用 7 天规则
- 空间公众号字段优先；未配置时回退 `config.json` 的名称、关键词和外部二维码 URL
- 后台上传的公众号二维码通过 `/group/official-qr/<空间名>.png` 提供；外部回退 URL 做可达性探测，失败时不输出裂图
- 管理 RPC `getSettings()` 仅返回类型与有效天数，不返回 `adminToken` 等敏感信息

## 四、技术方案

### 4.1 落位

功能集成在现有 backend 主应用，不另建独立服务：

- 数据模型：`GroupSpace`、`GroupQRCode`、`GroupStatDaily`
- 服务层：`apps/backend/src/services/GroupEntryService.ts`
- 公开路由与旧脚本 API：`apps/backend/src/server/groupEntry.ts`
- 管理 RPC：`apps/backend/src/api/authApi/groupEntryApi.ts`
- 管理页面：`apps/website-frontend/src/pages/admin/GroupEntryManagement.vue` 及 `groupEntry/` 子组件
- 图片存储：`uploads/group-entry/` 本地持久化目录，不引入 OSS；图片路径解析限制在上传目录内

迁移 `20261029000000_group_space_from_param` 将旧 GroupProject 改名重建为 GroupSpace（沿用 id），公众号单例配置回填到每个空间，群码 `projectId → spaceId`，统计表重建为 `date+space+from` 主键（存量 from 记空串），并删除 GroupEntry / GroupProject / GroupOfficialAccount。

### 4.2 缓存策略

- 动态图：`Cache-Control: public, max-age=300`
- 落地页：`Cache-Control: no-store`
- 数据库公众号图片使用内部受控路由，不对外部地址做服务端 HEAD；旧配置的外部图片仍有 3 秒探测和 5 分钟结果缓存

### 4.3 部署

- 使用现有服务域名下的 `/group/...` 路由，HTTPS 必备
- 上传目录必须持久化；发布沿用既有 backend 发布流程
- **线上数据库迁移前必须先用 scp 备份 SQLite 数据库，备份成功后才允许迁移**
- 本地测试项目和测试公众号配置不会自动部署；上线后需在后台配置真实公众号信息

### 4.4 安全

- 管理 RPC 必须具有有效登录会话和管理员角色
- 独立 HTTP API 使用 `x-admin-token`，缺失时该组接口禁用并记录日志
- 上传仅允许 PNG/JPEG/WebP，最大 5MB
- 动态图和落地页不暴露群码本地路径；公众号图片路径同样限制在上传目录内
- 统计仅管理员或持有效管理 token 的脚本可访问

## 五、验收标准

1. 同项目两个入口始终展示同一张当前群码，统计仍按入口独立记录
2. 连续上传两张有效码时，第一张保持当前出码，第二张进入等待队列
3. 当前码标记 `FULL` 后，同项目所有入口自动切到下一张有效码；无有效码时显示公众号主引导
4. 有效入群页同时展示群码和公众号；无有效码页不展示死码或裂图
5. 动态图在状态切换后按缓存策略更新，无有效码时仍返回 200 提示图
6. 公众号文字配置与二维码可在后台保存，刷新和公开页均展示最新内容
7. 管理页移动端无横向溢出，暗色模式正常，控制台无 Vue 警告或应用错误
8. `GET /group/admin/stats?days=30` 能按入口返回 PV/UV

## 六、明确不做

- 不做同一入口同时向多个私域空间分流、轮询或 A/B 路由
- 不做定时任务；过期判断在请求时惰性计算
- 不接企微，不做活码平台对接
- 不另建独立用户体系，复用主后台管理员权限
- 不自动探测微信群是否真实过期或群满
